# Wenyi 前端框架重构计划（P0 + P1 + P2）

依据 [docs/design/frontend-framework.md](V:\wenyi-renais\docs\design\frontend-framework.md) 落地前三阶段；P3（逐页加载态清理）作为后续独立任务，P4（数据路由迁移）不做。在 main 上分 5 个提交，每个提交点全绿。

## 新增文件

| 文件 | 职责 |
|---|---|
| `packages/ui/src/routes/manifest.tsx` | 单一事实源：13 条路由（lazy + loader）+ 全局/项目导航元数据（label、icon、顺序、audience、end） |
| `packages/ui/src/routes/RouteGate.tsx` | 路由内容区统一边界：`RouteErrorBoundary(resetKey=pathname) → Suspense(quiet gate)` |
| `packages/ui/src/routes/LazyBoundary.tsx` | 组件级 lazy 标准包装（Suspense + 可选 fallback），供 Accounting / ProviderSettings 使用 |
| `packages/ui/src/routes/AppErrorBoundary.tsx` | 全局根级边界（兜 shell/Provider 崩溃），由现 `RouteBoundary` 改造 |
| `packages/ui/tests/routing-rules.test.mjs` | 静态护栏（见 Step 4） |

## Step 1 — 提交①：先落"当时即可绿"的护栏测试（P0a）

不改任何产品代码，只加测试，锁定现状防止重构回归：

1. **shell 同节点断言**（`apps/web/tests/interface-structure.spec.ts` 或新 spec + `apps/desktop/frontend/tests/desktop.spec.ts` 各一条）：`goto("/")` → evaluate 把 `#sidebar-navigation` 存到 `window.__nav` → 点 Settings 链接 → 断言 `window.__nav === document.querySelector('#sidebar-navigation')`（导航前后是同一 DOM 节点）。
2. **通配重定向测试**：访问 `/no-such-page` → 断言重定向到 `/`（web 端一条即可）。
3. **13 条路由 chunk 全量断言**：扩展 `packages/ui/tests/platform-boundaries.test.mjs`，把硬编码 4 条改为按 `manifest` 预期清单（此步先硬编码 13 个文件名，Step 4 后可改为从 manifest 读取）——Web dist 与 Desktop dist 都断言。

验证：两端 `typecheck:tests` + 受影响 e2e。

## Step 2 — 提交②：路由清单化（P1a）

1. `manifest.tsx` 用现有 `lazy(() => import(...))` 定义 13 条路由；`nav` 元数据严格复刻当前 DOM 顺序与可见性规则：
   - 全局组 order：projects(10) / create(20) / settings(30)，`end` 在 `/`；
   - 项目组 order：overview(10, end) / proofreading(20, book) / review(30, book) / subtitles(40, srt) / glossary(50, book) / style(60, book) / contents(70, book) / export(80) / settings(90) / events(100)；`book = format && format !== "srt"`、`srt = format === "srt"` 与现逻辑等价 → 书 9 链接、字幕 5 链接、侧栏合计 12，sidebar/navigation e2e 不动即绿。
2. `App.tsx`：路由表改为从 manifest 生成（`element` 直接用 lazy 组件；`* → /` 保留手写）；启动预热 effect 改为遍历 manifest 的 loader（删除手写 `routeLoaders` 数组）。
3. `Navigation.tsx`：`ProjectNavigation` 与 `AppLayout` 全局导航的链接数组改为映射 manifest（`NavigationLink` 组件、props、DOM 全部不变；可见性由 `audience + format` 计算）。
4. 验证：两端 typecheck/build、`test:frontend-boundaries`、**两端全量 e2e**（侧栏计数、导航结构、desktop 全套）。

## Step 3 — 提交③：统一边界（P1b）

1. `RouteGate.tsx`：
   - 错误边界类组件 `resetKey = location.pathname`（切页自动复位，ZCode `resetKeys` 语义）；fallback 为 `<div role="alert">` + `runtime.pageFailed` 文案 + Reload 按钮（`location.reload()`——React.lazy 失败会缓存拒绝，无 reload 的 retry 不可靠，故保留 reload；`<div>` 而非 `<main>`，避免 main 嵌套）；
   - `Suspense fallback = <div aria-busy="true" className="route-placeholder" data-route-pending="" />`（与现 AppLayout 内 fallback 逐字段一致，desktop e2e 的 `[data-route-pending]` 断言原样通过）。
2. `AppLayout.tsx`：`<Outlet />` 外包 `<RouteGate>`，删除内联 Suspense。
3. `App.tsx`：删除顶层 `RouteBoundary` 与外层 Suspense（及其 `runtime-placeholder` fallback），换成 `AppErrorBoundary`（全屏 `main role=alert`，同 i18n key）。
4. `LazyBoundary.tsx` + 替换手写组合：`Accounting.tsx`（保留文字 fallback prop）、`ProviderSettings.tsx`（fallback=environmentField）。
5. 删除死代码：`App.tsx` 的 `RouteError` 移入 `RouteGate.tsx` 复用。
6. 验证：同 Step 2 全链 + desktop `lazy route pending / lazy route failure` 两个专项 e2e + **真机 CDP 冷/热导航复测**（沿用本会话方法：刷新 → 立即点设置 → 断言 shell 同节点、占位时长）。

## Step 4 — 提交④：静态护栏（P0b，写给重构后的代码）

`packages/ui/tests/routing-rules.test.mjs`：

1. **Suspense 白名单**：`packages/ui/src` 内 `<Suspense` 只允许出现在 `routes/RouteGate.tsx` 与 `routes/LazyBoundary.tsx`；`App.tsx`/`AppLayout.tsx` 必须 0 处（结构性禁止"Suspense 高于 shell"）。
2. **lazy 配对规则**：任何含 `lazy(` 的文件必须同时含 `<Suspense`、`LazyBoundary` 或显式预热调用（`void load...`）之一；`routes/manifest.tsx` 豁免但必须满足下一条。
3. **manifest 完整性**：13 条路由均有 loader；导航 entry 的 route 引用可解析；启动预热遍历 manifest（源码断言 effect 存在）。
4. 根 `package.json` 的 `test:frontend-boundaries` 改为 `node --test packages/ui/tests`（目录形式，自动发现两个测试文件）。
5. 验证：`pnpm test:frontend-boundaries` + 两端 build（chunk 断言依赖 dist）。

## Step 5 — 提交⑤：意图预取（P2）

1. `NavigationLink` 增加 `prefetch?: () => Promise<unknown>`，`onPointerEnter`/`onFocus` 触发（幂等，import 缓存）；`Navigation.tsx` 从 manifest 取对应 loader 传入。
2. 不做数据预取、不做页面内 `Link` 预取（范围收敛）。
3. 验证：两端 typecheck + 受影响 e2e（导航 hover 不改变行为，e2e 应全绿）+ 手动冷启动点按顺序 hover 后进入无占位。

## 风险与保底

- **侧栏 e2e 是最敏感回归面**（链接计数/顺序/aria/title、240↔64px 宽度）：manifest 输出必须逐字段复刻，Step 2 单独成提交便于二分。
- **desktop `[data-route-pending]` 三处断言**（aria-busy、空文本、`#sidebar-navigation` 可见）：RouteGate fallback 逐字段保持现值。
- 页面内 `Link`（Dashboard 卡片、面包屑等 20+ 处）**不动**——它们是内容链接不是导航面。
- Windows 本地 e2e 需手动起 Vite（4173/4174）再跑 playwright；Playwright Chromium 已装。
- 每个提交独立可回滚；若 Step 2/3 引发意外 e2e 失败，先修复再前进，不带病提交。
