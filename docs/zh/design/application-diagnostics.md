# Desktop 应用级日志保存与诊断包导出

[English](../../design/application-diagnostics.md) · [已实现架构](../architecture.md)

## 状态与建议

**Desktop 基础功能已实现，扩展设计仍分步推进。** 初次审查基于 `201158c`。已交付行为见[使用文档](../desktop.md#诊断与反馈)；下文章节保留完整目标要求，不代表所有规划控件和观察点均已完成。

已实现：原生层管理的有界保存/轮转和内存降级，安全的原生/引擎/前端记录，任务/call/错误关联，临时详细采集，设置页及错误页导出，原生菜单/快捷键和早期故障导出，原生目标位置接纳、ZIP 校验与原子发布。原生进程是**唯一写入者**：Python 通过既有私有管道发送有界、独立校验的 `WENYI_DIAGNOSTIC` 消息，保留 `WENYI_READY` 消息格式，仍丢弃任意 stderr。ZIP 按来源拆分，磁盘文件按会话混合保存各来源。

尚待实现：项目/运行筛选、任意日期范围、配置/项目/用量摘要、更完整的环境信息、阶段/检查点心跳覆盖、通用重复聚合及错误优先选择。当前按本次启动/24 小时/7 天选择该 Desktop 工作区的日志，记录预算 20 MiB、ZIP 上限 25 MiB。任务返回记为 `task_finished`（返回可能表示成功或暂停），持久任务状态仍是权威；不复制原始事件文件或账本。

**仅面向 Desktop**，采用**本地优先、结构化、默认隐私安全的应用日志**，由用户主动导出诊断 ZIP。覆盖原生壳、本地 Python 引擎和 Desktop 前端，包括引擎或 React 界面尚未启动的故障。不自动上传报告。

CLI 命令、Web 浏览器报告、服务端/容器日志收集及跨平台诊断 API 均不在范围内，也不是本方案的后续阶段。实现优先放在 Desktop 适配层；只有 Desktop 确实需要可选观察钩子时才扩展共享代码，不改变 CLI/Web 日志行为。

| 方案 | 取舍 | 决策 |
|---|---|---|
| 保存全部控制台输出并打包工作区 | 收集简单，但会暴露密钥、书籍和无关数据，且缺少结构化关联 | 不采用 |
| 将所有应用故障都塞进项目事件 | 复用存储，但无法覆盖项目/数据库初始化前的错误，混淆清理策略与持久历史 | 不采用 |
| 应用日志、项目事件、用量账本分离，只导出安全投影 | 边界明确、空间有界，可跨层定位问题 | **推荐** |
| 引入远程崩溃上报/可观测服务 | 增加隐私、部署和可用性义务 | 本方案不需要 |

## 1. 现有基础与原始缺口

- [项目事件 API](../../../packages/backend/wenyi_backend/routers/events.py#L13) 读取已保存的任务事件，不是进程级日志服务。
- [Desktop 子进程启动](../../../apps/desktop/src/process.rs#L112) 为避免泄露凭据，主动丢弃引擎 stderr。[引擎入口](../../../apps/desktop/backend/wenyi_desktop/desktop.py#L129) 将 stdout 留给就绪协议，其他输出转入 stderr。直接将 stderr 改为文件会破坏现有安全边界。
- 原生启动最初缺少独立于引擎的导出路径，现由[原生诊断控制](../../../apps/desktop/src/diagnostics_ui.rs#L1) 提供。
- [LLM 路由](../../../packages/core/wenyi_core/llm/router.py#L169) 已有 `call_id`、operation、attempt、路由及用量事件；[重试记录](../../../packages/core/wenyi_core/llm/retrying.py#L272) 已能分类重试而不记录请求/响应正文。应复用这些身份与分类。
- 现有凭据作用域错误保护**不是全局保证**：[未提供凭据快照的 provider 路径](../../../packages/core/wenyi_core/llm/router.py#L260) 仍可能重新抛出 SDK 异常，[任务失败处理](../../../packages/backend/wenyi_backend/workers/tasks.py#L292) 可能保存 `str(error)`。不能假设旧事件和错误可安全直接打包。
- [共享 HTTP 解码](../../../packages/ui/src/lib/http.ts#L2) 保持原有契约；Desktop 在自己的适配器中补充错误编号显示，UI 错误边界调用可选的 Desktop 观察钩子，不转发异常内容。
- [Backend context](../../../packages/backend/wenyi_backend/context.py#L152) 和 [UI platform services](../../../packages/ui/src/platform.ts#L33) 已提供合适的注入入口，可只为 Desktop 接入诊断能力，不让共享代码导入 Desktop 实现。

### 三类记录保持分离

| 记录 | 回答的问题 | 权威性与生命周期 |
|---|---|---|
| 应用诊断日志 | 启动、界面、I/O、任务执行或依赖为什么出问题？ | 尽力保存、限额轮转；不能用于恢复任务 |
| 项目事件 | 这个项目/运行发生过什么？ | 保留现有 Storage 历史；本功能不改变清理和业务语义 |
| 用量账本 | 实际产生了多少模型用量？ | 保留持久化、只合并一次的记账规则；日志不是第二套账本 |

后两者只导出安全投影。清理应用日志不得改变项目、检查点、Review 产物或用量余额。

## 2. 用户操作流程

### Desktop 操作入口

增加**设置 → 诊断与反馈**，提供四组操作：

1. **导出诊断报告**：常规反馈入口。
2. **复制排查摘要**：版本、平台、错误编号、故障分类与建议下一步；不含文件路径或书名。
3. **开启详细日志 30 分钟**：明确临时开启 DEBUG，显示倒计时并可提前停止；重启恢复默认。隐私规则不变。
4. **打开日志目录 / 清理应用日志**：清理需确认，仅影响诊断数据，与正在写入/导出的任务协调。实际本地位置和占用可显示在界面，不进入复制的报告。

任务失败、导出失败、启动错误页提供相同导出操作，并预选相关错误/项目/运行。项目事件页链接到该入口，不改成全局日志查看器。首版不建设完整日志搜索控制台。

导出弹窗显示时间范围、范围选择、预计大小、包含/排除的类别。默认最近 24 小时，也可选本次启动、保留期内的上次启动，或保留期内的自定义时间。项目错误入口选中该项目；全局设置入口默认“仅应用”。仅应用包含全局生命周期/基础设施事件；项目范围只额外加入选中项目的任务记录，以及可选的安全项目事件/用量摘要。不得静默附带其他项目记录。

**先选择原生保存位置，再收集或生成压缩包**。取消选择不创建诊断任务或临时包。选好后仍可取消并清理临时文件；在目标同目录写完整临时 ZIP 后原子发布，覆盖现有文件需确认。诊断导出不是书籍导出任务，不占用书籍导出历史。

预览以包清单为依据，并明确说明版本、运行环境和时间信息仍可能具有识别性。用户可先在本地检查，再自行附到 issue。不得自动将报告塞入 issue URL、发网络请求或上传附件。

### 故障时也必须可用

- 增加不依赖 Python、React、项目目录库或工作区锁的原生菜单/对话框导出入口。即使启动失败，也能生成包含原生/引擎日志的部分报告。
- 在导入应用和重依赖前安装最小 Python 启动日志器；不改变就绪协议。不捕获任意 stdout/stderr；不受支持的更早期崩溃只保留原生启动/退出元信息。
- 在 React 挂载前安装前端错误钩子，通过有界、安全适配器记录路由/根错误边界、`error`、`unhandledrejection`，不整体录制 `console.*`。
- 上次会话缺少正常退出标记时标记为**非正常退出**，不能断言一定发生崩溃。SIGKILL、断电、解释器/原生 abort、WebView 销毁可能丢失缓冲记录；不自动收集内存转储或 core dump。
- 所有日志位置不可写时，保留有界内存摘要并说明证据缺失。原生可执行程序完全无法启动时，无法靠自身导出；文档应说明已有日志目录的人工获取方法。

## 3. 日志颗粒度

严重性与详细程度分开：默认采集 INFO 及以上，临时 DEBUG 增加细节。类别用于选择来源，不代表放宽脱敏。

| 级别 | 含义 | 示例 |
|---|---|---|
| ERROR | 用户请求的操作失败 | 任务失败、保存失败、重试耗尽 |
| WARN | 可恢复降级或需要关注的情况 | 重试等待、fallback、慢存储、凭据库不可用 |
| INFO | 有意义的生命周期/结果，而非重复进度 | 启停、任务接纳、阶段结果、逻辑模型调用完成 |
| DEBUG | 有界、无内容的实现细节 | 批次边界、缓存决策、安全栈帧、普通请求耗时 |
| CRITICAL | 应用或持久化服务无法继续 | 致命启动失败、工作区不可用；尽力刷新日志 |

用户取消/暂停、取消保存对话框、预期编辑冲突不记 ERROR。故障由负责该操作的边界记录一次；上层引用其 `error_id`，不重复打印整份调用栈。

| 范围 | 默认 INFO/WARN/ERROR | DEBUG 增补 | 永不记录 |
|---|---|---|---|
| 原生壳 / 引擎 | 会话启停、引擎 spawn/ready/exit、就绪耗时、退出状态、托盘/图形/更新/插件结果 | 安全的生命周期步骤耗时和状态转换 | 就绪载荷/token、原始子进程输出、panic 内容 |
| UI | 未处理/渲染失败、写操作结果、断连/重连状态 | 路由标识、有界操作轨迹、请求耗时 | DOM、输入值、剪贴板、截图、完整 URL |
| HTTP / IPC / WebSocket | 写操作结果、失败或慢请求、鉴权拒绝、连接状态变化 | 正常读取和 IPC 耗时 | header、查询串、body、认证消息、任意 IPC 参数 |
| 任务 / 阶段 | 接纳/开始/暂停/续跑/完成/失败；阶段起止、耗时和计数 | 批次/章节边界、缓存命中原因、检查点耗时 | 段落、章节名、译文、术语内容、Review 证据 |
| LLM | 每个逻辑 `call_id` 一条终态摘要；重试/fallback/耗尽、耗时、尝试次数和用量计数 | attempt 起止、配额/队列等待、路由决策 | prompt、messages、模型输出、SDK 异常正文或响应 body |
| 存储 / 导出 | 安全的迁移/恢复结果、锁冲突、失败/慢 I/O、导出格式/大小/结果 | 锁等待/持有时长、检查点/快照标识 | SQL 参数、数据库副本、绝对路径、原文/输出文件名 |
| 凭据 / 配置 | 校验结果、密钥可用性/来源类别、安全配置修订摘要 | 变更的白名单选项名称 | 密钥值、环境变量全集、原始 YAML/JSON、自定义 header 或 URL |

具体控量规则：

- INFO 不按 token、段落、进度 tick、轮询、渲染逐条记录。批次细节放 DEBUG；阶段结束记录聚合数量。
- 活跃任务至多每 60 秒记录一次不含内容的摘要：阶段、完成数、在途数、等待最久的 `call_id`/耗时、距上次检查点时间。不启用 DEBUG、不新增模型请求，也能区分“请求很慢”与“执行停止”。
- HTTP/IPC/存储操作默认超过 2 秒记 WARN；锁等待与持有时长分开。长任务接口和模型调用按配置超时/阶段摘要判断，不机械套用 2 秒阈值。
- 按类别、错误码、安全栈指纹和作用域聚合重复故障：保留首条，之后至多每 60 秒写一次次数及首末时间摘要。不同项目/运行不得合并；独立终态失败始终尝试保留。
- 临时 DEBUG 不开启 SDK/HTTP 原始正文跟踪。DEBUG 流同样有界，采样和丢弃必须可见。

## 4. 结构化格式与关联关系

采用 UTF-8 JSON Lines，每行一个完整对象。人类可读文本从同一条记录生成，不另维护第二套日志。消息/事件名使用稳定英语模板；UI 标签和摘要可本地化。

必需字段：`schema_version`、UTC `timestamp`、`level`、`event`、`event_id`、`component`、`app_version`、`session_id`、`process_instance_id`、进程内递增 `seq`、白名单 `attributes`。`message` 可选且只能是固定模板。`duration_ms` 使用单调时钟，不用系统时间相减。

| 上下文 | 规则 |
|---|---|
| `session_id` | Desktop 壳每次启动生成，传给引擎和前端；不建立永久机器标识。 |
| `process_instance_id`、`seq` | 区分进程重启并确定单进程顺序，不能只依赖 PID；跨进程时间排序仅是近似。 |
| `project_id`、`run_id` | 复用 Desktop 现成的不透明身份，不使用标题/路径衍生的名称；不改变续跑身份，不为日志增加书籍状态。 |
| `request_id` | 单次回环 HTTP 请求经验证/引擎签发的关联号，通过 `X-Request-ID` 返回并由 CORS 向 Desktop 前端暴露；与 provider 请求 ID 区分。 |
| `call_id`、`attempt` | 复用现有模型调用身份，重试/fallback 保持关联；不另建竞争性 LLM trace ID。 |
| `error_id` | 由负责失败的边界生成，在 Desktop 显示，贯穿回环 HTTP/任务/原生记录；新的独立失败使用新编号。 |
| 可选作用域 | 已注册 operation、阶段、数字章节/批次索引、导出/审校身份；不带标题或内容 |

将请求上下文传入已接纳的本地任务元信息，本地运行器入口恢复作用域；裸线程/线程池提交显式复制上下文。Desktop 宿主绑定诊断上下文，Core 不反向导入 Backend 或 Desktop 获取它。上下文在**入队前**捕获，不能由日志线程读取别的任务的当前上下文。结束时恢复作用域，并测试并发项目和相互隔离的 Desktop 工作区。

保留回环错误响应现有面向用户的 `detail` 兼容性，在适用位置由 Desktop 适配器增补结构化 `code`、`error_id` 和请求关联信息。拒绝不合法/无限长的传入 ID，替换为新生成值。前端声称的引擎/运行身份必须与已认证操作核对，不能直接信任；无需改变 Web 错误契约。

## 5. 隐私是入口规则，不是打包时补救

1. **事件 schema 与字段类型白名单。** 优先枚举、数字、布尔值和不透明引用；未知字段省略。字段名在白名单中不代表任意字符串安全。
2. **进入队列、文件、控制台 sink、崩溃钩子前处理。** 队列仅接收不可变安全记录，不保存带 `args`、异常或 request 对象的原始 `LogRecord`。未知第三方消息只保留类别/次数或省略，不将不受限的 root logger 接到持久化 sink。
3. **保留可定位信息，不保留异常内容。** 记录白名单异常类别/码、状态、可重试性、包内相对栈帧/函数/行号。除非专用安全分类器生成固定文案，否则不记录 `str(error)`、cause 消息、局部变量和源码行。JS 栈规范化资源路径并去掉 URL，无法识别的帧省略；Rust panic 内容同样不可信。
4. **任何模式都不收集正文。** 排除原文、译文、提示词、模型响应、术语内容、Review 证据、任意进度标签、用户自定义配置文本。私有项目名、源文件名和内容哈希都不充当诊断身份。
5. **配置规范化投影。** 可含注册的 provider 类型、白名单公共模型标识、operation/路由、超时/重试/并发限额、功能开关。自定义连接/模型名和端点使用别名；端点仅暴露内置/自定义/本地类别，不带主机、路径或 URL。凭据只记录可用性/来源类别，导出不读取密钥。
6. **导出身份假名化。** 项目/运行/会话/call/自定义标签在同一个包内一致映射，每个包使用新的随机作用域；不携带反向映射及其秘密。provider request ID 是不可信外部字符串，只保留不透明关联引用，不保存原始 header。保留生成的 `error_id`/`request_id` 供支持人员关联。
7. **导出时再次验证。** 旧事件 payload、未知 schema 和已有 `error` 字符串不能原样复制。项目/用量摘要必须重新构造白名单视图，不是对数据库/配置 dump 做关键词替换。

已知密钥替换只能作为纵深防御，不能保护书籍正文或未知凭据。支持的平台使用仅当前用户可访问的目录/文件权限，Windows 使用适当的用户 ACL。不能承诺假名化日志完全匿名。首版没有“包含原始数据”开关；涉及翻译内容的问题需另行征得同意、提供最小复现，优先公版文本。

## 6. 保存与失效处理

建议初始限额，实施时通过负载测试验证：

| 项目 | 默认值 |
|---|---|
| Desktop 位置 | `<workspace>/diagnostics/`，不放项目存储内；早期启动/降级使用原生平台的当前用户应用日志目录 |
| 本地保留 | 每个日志根目录 7 天**或**200 MiB，先触达先清理；总量含活跃文件和会话标记 |
| 轮转 | 单文件 10 MiB；文件名包含会话/进程/组件，一个文件仅一个写入者 |
| 详细模式 | 30 分钟，可手动停止，重启恢复；不增加保留期/容量预算 |
| 队列 / 单条 | 每进程最多 4,096 条，其中 512 个位置保留给 WARN+；单条序列化后不超过 16 KiB |
| 内存降级 | 每进程至多 256 条安全记录，**且**不超过 1 MiB |
| 刷新 | 普通缓冲最多 1 秒；退出/致命故障最多等待 2 秒排空；不逐条 `fsync` |
| 诊断 ZIP | 选中数据未压缩总量最多 100 MiB，最终压缩包最多 25 MiB |

路径、writer 初始化/关闭由 Desktop 入口显式决定；导入 Core 不配置日志或创建文件。禁止多个进程轮转同一文件。每个日志根目录由单个维护者使用**诊断专用锁**协调清理、读取和写入。触达上限但活跃文件无法回收时，降级采集，而非无限增长或删除活跃文件。启动日志根目录和工作区日志根目录各受上述上限约束，占用统计需同时展示。

队列饱和先淘汰/丢弃 DEBUG，再 INFO；预留位置只是提高 WARN/ERROR 送达率，不能承诺不丢失。高优先级队列也满时累计有界丢弃计数，恢复后写缺失摘要，并在包清单中体现。不能让翻译等待日志队列，也不能在持有领域锁时同步降级写盘。

权限不足、磁盘满、编码问题、writer 失败不得阻止翻译或掩盖原始异常。切换到有界内存，展示一次不递归的日志降级提示，并以有界退避重试存储；不得通过正在失败的 sink 循环记录其自身失败。

## 7. 诊断包契约

建议文件名：`wenyi-diagnostics-<UTC>-<short-bundle-id>.zip`，不带书名或用户名。

```text
manifest.json             # schema, scope, windows, completeness and file checksums
report.md                 # readable summary and copy-ready issue checklist
system.json               # app/build, OS/architecture, Python/WebView/plugin versions
config-summary.json       # allowlisted effective options, never the raw config
logs/native.jsonl          # available selected sources only
logs/engine.jsonl
logs/frontend.jsonl
project-summary.json      # optional selected project: format, counts, status, run references
project-events.jsonl      # optional safe event projection
usage-summary.json        # optional counts, not a copied ledger
```

只收集选定 Desktop 工作区/会话的来源；不存在的来源不建空壳文件，在清单中说明。系统信息排除主机名、用户名、环境变量和完整文件路径。不得包含原书、SQLite/WAL、源文缓存、整个项目目录、原始 manifest/config、凭据库、导出的书籍、截图、崩溃转储。

清单记录：

- 包/schema/应用版本，选中时间窗/项目范围，详细模式状态。
- 每个来源的采集时间窗和高水位，收集起止时间。这是有界诊断观察，**不是事务一致的项目备份**。
- 文件列表、SHA-256、字节/记录数，脱敏/省略字段和未知事件类型。
- 缺失/不可读来源、队列丢失、轮转缺口、异常/截断行、采样和大小截断；明确 `complete` 或 `partial`。
- 聚合故障类别和生成的错误编号，不含原始异常消息。

收集算法：

1. 确认保存位置后校验范围，获取短期诊断快照租约，固定相关文件与字节偏移；每个来源只读高水位前的完整行。轮转/清理不得移除被固定的来源；流式处理，不整文件加载。
2. 可选项目摘要通过现有只读 Storage/repository 接口和短读取作用域取得。读文件、脱敏、压缩期间不持有项目锁/SQLite 写事务。缺少按时间/数量限制的查询时增加有界读取投影，不能遍历全部章节/数据库行后才截断。
3. 应用 schema 投影及包内别名；只检查诊断子系统拥有的文件，拒绝符号链接/路径逃逸，不递归扫描工作区，压缩条目使用固定名称。
4. 优先错误及其前后上下文，再生命周期/阶段摘要、INFO、DEBUG；同时满足两个大小限制，并记录省略的时间窗/数量。可读报告由同一份过滤结果生成，不再次读取私有状态。
5. 验证条目/校验和/清单，刷新临时 ZIP 后原子发布。失败不留下看似成功的半成品；取消释放租约，只清理本次导出的临时文件。

可选来源读取各限 5 秒，总收集限 30 秒；慢/不可用来源生成明确标记的部分报告。无法证明安全的投影直接省略，最终包无法验证则不发布。校验和只证明完整性，不代表加密或匿名保证。

`report.md` 回答：版本/平台、故障/错误编号、相关阶段、首末时间、重试/fallback 历史、最后安全进度、缺失证据、建议下一步。复现步骤、预期/实际行为、是否已开详细日志作为由用户补充的 issue 清单；不能仅凭 timeout 断言根因。

## 8. Desktop 模块职责与接口

**实现归 Desktop 所有，不预建跨平台日志框架：**

- 原生壳：负责启动/会话上下文、原生结构化 writer、panic/子进程退出元信息、不依赖 UI 的收集、目标位置能力和 ZIP 原子发布；即使引擎不可用，仍由原生层协调导出。
- Python 引擎：Desktop 自有诊断模块负责安全事件投影、有界管道发送、回环请求/本地任务上下文。复用既有 LLM 事件；未来摘要使用只读本地 repository/Storage 接口。原生 writer 负责保存和轮转混合来源文件，引擎不另设文件写入者，不改书籍状态、不复制数据库。
- Desktop 前端：负责诊断设置区、React 之前的错误钩子、临时详细控制、安全操作轨迹及原生导出调用；不将诊断信息存入 WebView 浏览器存储，不使用浏览器下载。
- 共享代码：复用现有 Backend context 和 UI platform 注入。只有共享任务/错误组件实际需要时才新增最小可选钩子；未配置 Desktop 诊断适配器时维持原行为。Core、共享 Backend/UI 不导入 Desktop 模块，不为假设中的复用新增 Core diagnostics 目录或新包。
- Desktop 传输：IPC 校验事件名、类型、大小、速率和可信来源，不接收任意文件路径/读取请求。可选引擎摘要接口仅挂在已认证的 Desktop 回环应用，不放进共享 router。Rust/Python/TypeScript 使用共同的 Desktop schema 夹具与隐私测试，不相互嵌入运行时。

原生降级导出使用已经脱敏的文件，可以省略依赖 Python 的配置/项目摘要；不能为了导出启动错误而强行启动翻译引擎。复用原生保存能力和原子发布模式，不复用书籍导出任务接纳。

日志设置归 Desktop 诊断配置，不进入翻译配置快照；改日志级别不能使缓存失效或改变语义指纹。不规划诊断命令行、Web 下载接口或远程收集器。

## 9. 分期与验收

| 阶段 | 范围 | 完成标准 |
|---|---|---|
| P1 — Desktop 反馈 MVP | Desktop 安全 schema/投影，原生/Python/前端采集，有界轮转，错误编号，默认与 30 分钟详细模式，导出弹窗和原生启动失败兜底 | 用户无需控制台、无需正常引擎，就能复现并导出可用且不含内容的证据 |
| P2 — Desktop 排查深度 | 补齐阶段/call/存储观察、安全选中项目投影、上下文传播、长调用摘要 | 维护者可串联 Desktop UI/回环请求 → 本地任务 → 模型重试/存储故障；并发项目/工作区不会串日志 |

P1 应复用已有任务/LLM 元数据，不把基础隐私和必要错误关联推迟到 P2；正常路径与启动/权限失败路径一起交付。

必需验收场景：

1. 引擎 ready 前失败、引擎意外退出、Python import 失败、React 渲染/rejection 失败、保存失败、更新失败、凭据库降级均留下分类证据；原生宿主可运行时应有导出入口。
2. 将伪密钥/私有文本放进异常、嵌套 payload、类似 header 的值、provider request ID、路径、配置标签、panic、旧事件；**队列、文件、摘要、ZIP 内容和 ZIP 文件名**均不得出现，默认/DEBUG 一致。
3. 使用 fake client 覆盖 LLM 401/429/5xx/timeout/retry/fallback，不调用真实付费模型/解析服务；仍保留有用的安全栈位置、状态、次数和耗时。
4. 并发项目/app/线程上下文正确，重试复用 `call_id`；导出不改检查点、不重复记账、不改任务状态，压缩时不占写事务。
5. 导出同时轮转、磁盘满、权限拒绝、队列饱和、UTF-8/末行 JSONL 损坏、时钟变化、遗留会话标记、进程强杀；内存/磁盘有界，证据缺失明确披露。
6. 保存位置选择前后取消、拒绝覆盖、符号链接逃逸、ZIP 写入失败、来源超时、归档大小上限；不越权读取、不留下最终半成品。
7. Windows/macOS/Linux 的原生保存/启动行为；引擎不可用时原生菜单仍能导出。所有日志目录不可用时，返回部分内存/原生报告或明确可操作错误，不能静默成功。
8. 不可信 WebView 来源、未认证回环客户端不能提交或读取诊断数据；未配置 Desktop 适配器时，共享组件保持原行为，不暴露诊断界面/接口；CLI/Web 日志行为不变。

实施验证需包含受影响 Python 测试、Ruff check/format、`git diff --check`，架构边界与上下文隔离测试，Rust 测试与打包后的原生启动/保存验收，Desktop 前端 typecheck/build 和受影响 Playwright E2E。若改共享 UI，仍按仓库规则做两端 typecheck/build、受影响 E2E 和前端边界检查；这是防回归要求，不代表交付 Web 功能。改动存储适配或 pipeline 装配时，触发仓库要求的存储/orchestrator 检查及高风险全量回归。

实施过程中保持 Markdown 链接、源码引用和中英文同步。验证结果需区分离线测试、浏览器 IPC mock 与打包后 Windows/macOS/Linux 原生对话框验收；数字限额不代表已经完成真实模型质量或负载验证。
