# Desktop 多项目并行工作流

[English](../../design/multi-task-execution.md) · [使用指南](../desktop.md#3-创建翻译项目)

## 范围

**仅实现 Desktop 后台。** 多个项目独立执行，不设置固定工作流数量上限。用户继续使用现有项目页面和操作。

撤回此前的任务中心方案：不增加导航、任务列表、角标、批量操作、聚合接口或前端调度器。Web 并行后续独立设计和实现，不改变 Web worker 限制、队列投递、导出及 CLI 执行方式。

## 执行边界

- 解析、准备、翻译、章节翻译、Review、SRT 工作流可以跨项目并行；[项目写入互斥](../../../packages/backend/wenyi_backend/project_service.py#L46)仍然禁止同一项目的冲突操作。
- [持久化准入](../../../packages/backend/wenyi_backend/job_service.py#L31)仍先创建 job/run 身份和配置快照，再派发任务，并对拒绝提交执行补偿。现有 HTTP 契约和续跑语义不变。
- [LocalRuntime](../../../apps/desktop/backend/wenyi_desktop/local_runtime.py#L212)不再通过单消费者和长度 128 的准入队列串行处理工作流；每个已接受工作流都有独立异步监管任务。
- [Desktop 派发器](../../../apps/desktop/backend/wenyi_desktop/local_runtime.py#L198)为每次运行持有一个同步执行线程。单线程 executor 归该次运行独占，不是所有任务共享的固定槽位池；跨线程复制上下文。默认 executor 继续用于控制请求、快照读取和维护。
- [共享任务适配器](../../../packages/backend/wenyi_backend/workers/tasks.py#L316)调用显式注入的派发器；[backend context](../../../packages/backend/wenyi_backend/context.py#L160)默认使用 `asyncio.to_thread`，保持 Web 行为。共享代码不导入 Desktop，也不根据全局状态猜测平台。
- 导出继续使用两个独立消费者和有界队列；遥测缓冲仍有界。Core 编排与单个工作流内部的批次/初稿并发规则不变。

## 所有权、暂停与退出

运行时所有权包含已接受的监管任务、实际 worker 和取消清理。目录库任务已处于终态，不代表运行时已经空闲。

1. 调度前登记 run。重复投递已拥有或已终止的 run，不重复执行。
2. 一个工作流异常或暂停不取消其他工作流。每次真实运行独立创建客户端、停止信号和项目存储。
3. 超时或退出时只取消异步 worker 一次；共享适配器发送协作停止信号，并保护同步执行，直到它退出并保存检查点。
4. 退出前先停止准入。尚未进入适配器的监管任务直接持久化中断/可继续状态，不开始模型工作；worker 在第一条指令前被取消的情况也须恢复状态。
5. 等待全部活跃写入者和监管任务结束，再停止遥测并释放工作区锁。即使目录库已显示终态，更新安全检查仍须计算未结束的监管任务。
6. 保留崩溃后现有孤儿任务恢复与用户显式继续，不自动重启全部中断任务。

线程分配失败按普通任务失败处理：持久化对应 job/project 错误，不取消其他项目，也不让项目永久忙碌。暂时无法停止的任务继续保持所有权，不强杀 Python 线程。

## 资源语义

“不设置显式上限”指没有 Desktop 工作流数量门禁、信号量、可配置上限或默认线程池隐藏槽位上限，不承诺无限内存、线程、吞吐或供应商容量。

已配置的单次运行模型限制和原有重试策略继续生效。[每个路由客户端](../../../packages/core/wenyi_core/llm/router.py#L27)都有独立限流器；共享凭据不意味着这些计数会成为跨项目账号总配额。全局速率协调和 Web 容量管理不在本次范围内。

同时运行更多项目会增加内存占用和同时发生的模型费用。导出容量和遥测缓冲上限属于这些组件的资源策略，不是工作流准入上限。

## 验证契约

全部回归数据使用临时目录，以假客户端和同步事件替代外部模型/解析服务。

- 将默认 executor 限制为单线程，三个或八个同步工作流仍在任意一个结束前全部进入执行；默认 executor 仍可处理控制工作。
- 执行前提交 129 个工作流，覆盖旧队列上限的移除。退出同时覆盖监管任务尚未启动，以及子 worker 在进入适配器前被取消的情况。
- 真实离线 HTTP 工作流同时保存三个独立项目的检查点。暂停或使其中一个失败不影响其他项目；继续获得新的运行身份，不重译已保存段落、不重复累计用量。
- 同项目重复准入仍被拒绝；项目/run 进度身份、独立客户端和应用上下文不串用。
- 保持重复派发、线程分配失败、导出容量、超时诊断、全部写入者退出、更新阻止及崩溃恢复的覆盖。
- 共享 worker 测试保留默认 Web 派发器及取消/导出行为。无需前端路由、HTTP schema、数据库迁移或依赖变更。

因涉及状态/恢复，运行受影响用例及完整 Python 测试集、仓库 Ruff check/format check、架构/orchestrator/存储契约和 `git diff --check`。缺少 PostgreSQL/Redis 集成测试服务时单独说明。离线检查不证明生产吞吐、极限负载稳定性或真实模型翻译质量。
