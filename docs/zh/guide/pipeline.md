# 翻译流程

文译先理解全书，再按章翻译并保存已完成工作，最后审校和导出。本页说明影响质量、
时间、费用及恢复的流程选择。命令见 [CLI 指南](cli.md)，选项见
[配置参考](../reference/configuration.md)，输入保留能力和导出限制见
[格式参考](../reference/formats.md)。

<a id="overview"></a>

## 默认流程

1. 解析并保存原文。
2. 准备章节梗概、文风指导和全书概览。
3. 翻译并润色章节，对齐格式，更新术语库。
4. 审校全书，开启 Autofix 时发布修订。
5. 导出已保存译文。

默认使用标准翻译，并开启全书理解、润色、注释对齐、最终 Review 和
**Autofix 发布**。三稿精翻和全书术语证据需要主动开启。
默认只导出单语版，双语版可选。

<a id="quality-and-cost"></a>

### 质量与费用取舍

| 选择 | 作用 | 成本或限制 |
| --- | --- | --- |
| 全书理解 | 第一批正文翻译前具备章节事实和全书背景 | 扫描全部章节原文，长章节需要多次预扫请求 |
| 润色 | 再次改善目标语言表达 | 标准批次通常增加一次模型请求；流畅不等于忠实 |
| 三稿精翻 | 三份独立尝试后，对照原文综合润色 | 正文阶段通常调用四次，标准翻译加润色为两次 |
| 注释／样式对齐 | 在译文中恢复链接和混合格式的位置 | 局部范围可能增加模型请求，不确定位置按格式降级 |
| Review 与 Autofix | 检查全书一致性、取证并修订 | 可能多轮审校并调用 Fixer；发布会改变正式译文 |
| 更多上下文或术语证据 | 提供跨段证据 | 提示词更长；生产术语证据还需额外请求 |

关闭某阶段会减少该阶段工作，但总费用不会必然按固定比例下降。
重试、输出长度、推理 token 和 provider 定价都会影响成本。
复用提示词前缀可能有利于服务端缓存，但不保证命中。
这些选项都不保证译文更准确；请比较代表性段落，并亲自检查重要结果。

<a id="preparation"></a>

## 翻译前的准备

解析不调用翻译模型，只识别章节和段落。`wenyi parse` 以及 Web/Desktop 上传解析
会保存只读的[原文快照](../reference/formats.md#source-snapshots)。
PDF 解析仍可能需要 MinerU 或 BabelDOC 服务。仅解析不代表翻译状态初始化完成。

`prepare` 或 `translate` 开头的准备阶段依次执行：

1. 当 `language.source` 为 `auto` 时识别原文语言；显式指定语言可跳过这次请求。
2. 开启 `pipeline.book_understanding: true` 时，概括**每章完整原文**，
   长章节按有界分块处理。
3. 以开头、中间、结尾的原文样本分析文风和人物语气，章节梗概提供事实背景。
4. 根据文风指导和章节梗概生成全书概览。

准备阶段**不翻译正文，也不抽取术语**。已有项目术语和导入映射会保留。
关闭全书理解只跳过章节梗概与全书概览，不关闭文风分析。

开启全书理解后，有文本的章节必须具备可用梗概才能开始正文翻译。
章节梗概失败会停止准备；全书概览失败则记录警告，允许依靠章节梗概继续翻译。
成功的整章梗概和文风分析可在身份匹配的重试中复用；
尚未完成的单章内部不逐块保存预扫检查点。

<a id="context-and-glossary"></a>

## 翻译上下文与术语库

章节和正文批次按原文顺序推进。常规批次获得文风指导、全书概览、本章梗概、
**当前全量术语库**、相关原文注释、最近译文、待译原文，以及一个后续原文片段作为只读参考。
后文参考帮助保持连贯，但不得提前翻译，也不计入当前输出段数。

最近译文从已保存的正式译文重建，可跨越前章。
`pipeline.rolling_context_tokens` 默认 512 token。
优先保留完整的最近段落；最近一段单独超限时只取其尾部。
预算设为零只关闭前文译文，不关闭后文原文参考。
BabelDOC 另有[按版面角色约束的上下文边界](../reference/formats.md#babeldoc)。

常规术语抽取从已完成的原译文对开始。因此，没有导入术语时，第一批正文没有预定映射。
新术语及冲突影响后续批次，不自动改写早先译文。
术语库是名称映射的权威来源；文风指导保留原文身份和人物描述。

每个待译正文批次都接收全量当前映射，包括本章未出现的词条。
新的 Reviewer 请求接收最终全量术语库。
这有利于提供全书一致性依据，但增加提示词长度；取证查询和单段 Fixer 可使用相关子集。

### 可选全书术语证据

`pipeline.terminology_context` 是默认关闭的 CLI 实验选项。
它在待译批次前发现人物，并结合全书匹配原文核实人物词条。
其他类型仍走常规译后抽取，准备阶段依然不预建术语库。

该功能增加发现、取证和合并请求，并向翻译、润色、Review 与 Fixer 提供有界的相关备注。
它保留权威译名和受保护的人工字段；不同的建议译名进入冲突流程。
备注只是补充证据，不授权提前泄露后续情节或补写原文没有的信息。
一个词条仍只有一个主译名，不是可按义项独立选译的模型。
取证失败不会发布局部知识；身份匹配的成功阶段可在重试时复用。

<a id="three-draft-precision"></a>

## 三稿精翻

`pipeline.translation_mode: three_draft_synthesis` 表示**三份独立初稿后，再做一次对照原文的综合润色**，
不是从三稿中选出胜者。该模式必须开启润色。

```text
同一份冻结原文与上下文
  ├─ 独立初稿 T1 ─┐
  ├─ 独立初稿 T2 ─┼─ 对照原文综合润色 → 最终译文
  └─ 独立初稿 T3 ─┘
```

三份初稿并发生成，互不可见。综合润色把它们作为可能有误的资料，优先遵循原文并融合有用部分，
没有独立的准确性裁判。保存的润色前对照是 T1，不是被认定最准确的初稿。

普通批次调用三次初稿生成和一次综合润色；
标准翻译加润色则各调用一次。两种模式使用相同的模型路由和输出上限。
四次与两次调用**不等于费用固定翻倍**：输入规模、输出 token、重试以及全书其他阶段仍要计费。

若初稿或综合润色在配置的重试次数内仍无法产生可用结果，当前批次会停止，
不会悄悄降级为逐段翻译。只重试失败阶段，兼容的成功初稿可在续跑时复用。

保持相同原文、模式、上下文及模型配置，才能复用待完成检查点。
切换模式不会重做已完成正式译文。命令及项目创建时的选择见
[CLI 指南](cli.md)和[配置参考](../reference/configuration.md)。

<a id="review-and-autofix"></a>

## Review 与 Autofix

Review 要求每章都已完成翻译。它用最终术语库检查连续原译文块，
可为不确定的问题取证、协调互相矛盾的建议，并提出修订。
额外轮次会重新检查修订后的文本，也会增加模型用量。

**`pipeline.review_autofix` 默认为 `true`，因此 Review 可以修改已保存译文。**
关闭 Autofix 后，新 Review 工作只生成建议，不将其发布到书籍中。

需要只获取建议、不开始发布时：

```bash
wenyi review book.epub --no-autofix
```

完整流程可设置 `pipeline.review_autofix: false`。
独立 Review 中，`--autofix` 可覆盖关闭的配置，强制发布。
**关闭 Autofix 阻止新发布，但已经开始、写入日志的发布会先恢复，
即使本次传入 `--no-autofix`，仍可能写回正式译文。**
该选项不是回滚命令，也不能取消已经提交的发布计划。

`pipeline.review: false` 或 `translate --no-review` 只跳过自动 Review。
显式 `wenyi review` 仍会执行。内容、术语、指导信息、语言策略及模型身份匹配时，
会复用完成结果或续跑未完成工作，**并非每次调用都新建 Review**。
这些输入变化时可能需要新一轮运行和新的模型费用。

Review 可能在轮次耗尽、仍有未解决问题、没有进展或出现修订循环时停止。
后续审校未再报告某问题，不证明替换内容正确。
准确性要求高的用途应先检查保存结果，再决定是否采用发布文本。

<a id="pause-and-resume"></a>

## 暂停与续跑

使用相同原文、目标语言和兼容配置重新运行。
CLI 状态按 `state/<book>/targets/<target-language>/` 隔离，
Web 和 Desktop 则保存各自独立的项目状态。同名但内容不同的文件不是同一份原文。

- 已完成正文批次保持保存；改变润色或翻译模式不会自动重做。
- 续跑可能先为已经翻译的批次补齐术语抽取，这不代表重新翻译该批次。
- 准备、精翻和 Review 复用身份匹配的成功检查点，不重复请求已完成模型阶段；
  没有持久成功记录的在途工作可能需要重新请求。
- 语言策略或提示词变化可能重建受影响的派生指导并产生模型用量，
  但保留已完成译文和术语。
- 翻译收尾可重试曾经失败的注释定位。因此，即使正文全部完成，
  再执行 `translate` 也不保证完全不调用模型。

用 `wenyi status` 查看保存进度，用 `wenyi inspect-run` 查看已记录的事件、用量及耗时。
累计 token 包括早先尝试和续跑，不只是最近一次命令。
恢复时保留状态与原文文件；需要完整重译或对比时，使用独立项目或状态目录。

<a id="re-export"></a>

## 不重译，只重新导出

`wenyi assemble` 从保存状态生成产物，**不调用翻译模型**。
更换格式、双语顺序、原文样式或导出专属标点规则时使用它，
不会重新准备、润色、Review 或修复注释。

每次导出使用同一时点的已保存书籍快照。
另一个流程可以继续翻译；之后保存的新批次需要再次导出才能包含。
导出仍可能需要原始模板；PDF 还可能需要 BabelDOC 会话。
详见[导出快照](../reference/formats.md#export-snapshots)
及 [PDF 要求](../reference/formats.md#pdf)。

检查点所有权、发布日志、缓存身份与账本规则见
[开发者流程契约](../development/pipeline.md)。
