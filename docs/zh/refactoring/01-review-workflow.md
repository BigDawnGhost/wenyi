## 证据与范围

[`review_workflow.py`](../../../trans_novel/pipeline/review_workflow.py) 共 1,891 行。707 行的 `run_session()` 长达 717 行，1425 行的 `review_chapter()` 为 397 行。前者同时管理检查点转换、影子覆盖、连续干净轮数、阻塞问题、循环检测、修订历史、结果组装和用量落盘；后者包含缓存查找、初审、证据循环、自适应拆块、单段重试和并发合并。

这些职责会交叉变化：增加一个终止条件时，现在必须在同一个大函数中推演恢复状态与最终未解决问题。只换文件位置不能解决这一点；本方案调整职责所有权，保留现有策略。

## 建议边界

| 建议模块 | 负责 | 不负责 |
| --- | --- | --- |
| `review/session.py` | `ReviewSessionState`、`RoundResult`、覆盖与阻塞状态，纯 `after_scan` / `after_fix` 决策 | 文件、客户端、线程池 |
| `pipeline/review_checkpoint.py` | 现有检查点的编解码，通过 `ReviewRunStore` 校验身份并选择续跑记录 | 判断问题是否已经修好 |
| `pipeline/review_chunks.py` | 初审、自适应恢复、缓存复用、章节术语延迟加载、稳定合并审校块 | 全书终止策略和正式发布 |
| `pipeline/review_rounds.py` | 单轮章节审校、归一化、冲突仲裁与影子候选生成 | 跨轮状态和正式译文写入 |
| `pipeline/review_results.py` | 净修订、未解决问题、结果与诊断组装 | 额外模型调用 |
| `pipeline/review_workflow.py` | `ReviewService` 的会话协调与 I/O 顺序 | 用长嵌套闭包共享大量可变状态 |

`ReviewService` 独占一份可变会话状态。轮次执行器接收有效译文的只读视图并返回结果；纯决策返回明确的下一步与新状态，协调器在现有边界执行检查点写入和用量刷新。不引入通用事件溯源引擎或任意工作流执行器。

## 续跑契约

| 已落盘边界 | 必须保留的续跑行为 |
| --- | --- |
| 内容、配置、术语匹配的已完成 Review | 直接返回结果，不重复模型工作。 |
| 尚无已完成扫描检查点 | 复用有效审校块和 agent 产物，补完本轮扫描。 |
| `phase=scan_done` | 恢复本轮问题及快照，从决策或修订继续，不重新扫描本轮。 |
| `phase=round_done` | 恢复覆盖、阻塞问题、计数和修订历史，再进入下一轮。 |

保留减少轮次限制后的恢复行为、独立干净确认、未解决修订失败、无进展终止及 A/B/A 循环拒绝规则。“保存扫描检查点 → 刷新扫描用量 → 开始修订”的顺序也是提取基线。盲审只看到有效影子译文，不携带上一轮问题描述；此处正式章节、manifest 和术语库保持只读。

## 实施切片

1. 增加有类型的会话和检查点转换，不改 JSON 键名、默认值；固定编解码和完整运行与续跑的对应行为。
2. 提取覆盖、问题、结果的纯函数及决策函数，原调用位置先保持不变。
3. 先提取审校块执行，再提取单轮执行；线程池留在这些服务中，保留先查缓存、后匹配术语，以及同章一份延迟加载术语快照。
4. 最后将 `run_session()` 收敛为加载恢复、执行、决策、检查点和收尾。Runtime 用量和最外层计时范围不变。

提取 agent 相关执行前先使用 02 的纯契约；03 仍是独立发布器，不并入此协调器。

## 验收

现有测试锚点：`tests/test_review_polish.py` 覆盖格式失败拆块、单段恢复、并发顺序和术语共享；`tests/test_orchestrator.py` 覆盖干净确认、阻塞失败、循环、trace 复用与异常用量；`tests/test_routing_resume.py` 覆盖账本恢复。

新增在 `scan_done`、扫描用量刷新、`round_done` 前后的故障注入；比较续跑与完整运行的公开问题、净修订、阻塞问题、请求集合及规定顺序、累计用量。确认缓存命中仍避免重复术语与证据准备。若涉及性能变化，用合成多章节数据测冷启动和续跑启动，不能用行数减少代替性能结论。运行全量测试和两项架构契约。

未来语义检索可以在轮次边界替换证据查询实现；新的质量策略扩展显式决策，不再修改会话 I/O。本次重构不实现这些新能力。
