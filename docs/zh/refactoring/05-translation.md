已实施：标题规划与语言感知的标题 Agent 保持独立；正文通过隔离的 BatchPlan 输入与 BatchResult 输出调用翻译和润色执行器。只有章节服务写入译文及润色前值，保留译文→对齐→上下文→术语检查点的顺序。续跑批次选择和只读后文参考行为不变，新增开启及关闭润色时术语检查点前中断的回归测试。

与 `dev` 整合后：`BatchPlan` 携带 MinerU 空译文策略；执行器优先延续翻译对话润色，必要时回退为独立润色，并保留过滤段落的位置。续跑按 token 预算分批，已保存的空译文视为完成，仅 `None` 表示待翻译。

## 证据

[`translation.py`](../../../trans_novel/pipeline/translation.py) 共 791 行。488 行的 `translate_titles()` 为 258 行，约占三分之一，包含续段回并、标题和 TOC 复用、待翻标题分批、提示词、模型结果校验、manifest 检查点。197 行的 `translate_chapter()` 为 219 行，协调正文批次、上下文、术语恢复、注释、样式和章节完成。

两者是不同的工作流。正文批次依赖前文译文，继续串行执行；拆文件不等于授权并行翻译章节内批次，也不引入自动相同句复用。

## 建议边界

| 模块 | 职责 |
| --- | --- |
| `pipeline/title_translation.py` | `TitleTranslationService`：规划正文标题和 TOC 复用，识别待翻条目，提交已校验标题批次，同步章节标题。 |
| `agents/title_translator.py` | 渲染现有标题提示词，调用 `translation.title`，校验数量与字符串，返回标题；不访问 manifest 或 store。 |
| `pipeline/translation_batch.py` | 有类型的 `BatchPlan` / `BatchResult`、考虑续跑的批次选择，以及只做翻译和润色的执行器。 |
| `pipeline/translation.py` | 串行章节执行、应用结果、提交顺序、滚动上下文、术语检查点和完成状态。 |

`BatchPlan` 包含章节身份、绝对正文段落位置、原文、术语快照、不可变的已渲染上下文、全书概览与章节摘要、注释上下文切片、紧邻的一条后文。`BatchResult` 返回对齐后的译文和润色前文本。将现有 `target_before_polish` 修改集中到一个明确的结果应用位置，但不改变最终保存的内容。

不能把存储访问、状态修改和模型调用藏进通用批次回调。主服务仍应直接展示译文、对齐、上下文、术语何时落盘。纯辅助函数只接收明确依赖，不传整个 Runtime。

## 必须保留的行为

标题翻译保留原始书名和 TOC、锚点身份。仅按现有原文匹配规则复用完整正文标题译文，包含续段回并；不能因为字符串相同就合并不同位置。保留每批 40 个标题、4,000 字符的现有边界、提示词、operation ID、输出校验和逐批 manifest 保存。

新翻正文批次维持现有顺序：赋值并保存译文 → 注释和 DOCX 对齐 → 重建滚动上下文 → 事件和进度 → 术语抽取、检查点及翻译历史更新；最后再做章节级术语抽取与章节完成提交。已有完整译文的批次恢复上下文，补齐缺失对齐和术语工作，不重复翻译。

紧邻的一条后文仍仅供翻译和润色参考，不计入输出、不当作已翻批次保存、不加入滚动译文上下文。保持同章节限制，以及单段回退时实际相邻后文的选择规则。

## 切片与测试

1. 先提取标题复用与规划纯函数，再拆标题 agent 和 service，保持 `TranslationService.run` 的调用顺序。
2. 增加批次输入输出类型，将翻译、润色计算移出，持久化仍在 `translate_chapter`。
3. 仅在测试能证明有独立边界时继续提取续跑选择，不为每个五行辅助函数新建模块。

`tests/test_assemble.py` 验证标题数量、正文标题复用、共享 XHTML 的 TOC；`tests/test_orchestrator.py` 验证部分批次、批次预算变化、术语检查点和跳过时的快照；`tests/test_translation_context.py`、`tests/test_translator.py` 验证后文参考。另跑术语、注释、DOCX、计时和架构测试；修改批次执行时跑全量。

在译文保存后、术语检查点前注入中断，续跑应只补账，不再次调用翻译。比较 operation、消息、保存的章节和 manifest，包括润色前文本。标题提取本身不能使已经完成的正文批次缓存失效。

未来翻译记忆和基于证据的风格分析，可以通过明确的批次输入接入，但另做功能设计。精确或语义匹配都需要上下文与来源策略；本次不把“原文相同”当作无条件缓存键，也不在没有证据时确定哥哥、弟弟等关系。
