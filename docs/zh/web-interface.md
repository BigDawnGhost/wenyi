# Web 工作流布局

[English](../web-interface.md) · [界面语言](web-i18n.md)

项目导航将 **翻译总览**、**人工校阅**、**全书审校**、**术语表**、
**风格 & 概要**、**导出**、**项目配置**、**事件日志** 全部平铺，并高亮当前页面。
桌面与手机共用一套导航；字幕项目使用字幕编辑器替代
书籍校阅／审校，不显示术语和风格工具。界面语言仍只在全局设置中调整。
桌面侧栏上方显示项目功能，下方固定放置项目列表、创建项目和设置。
手机端也按项目导航在前、全局入口在后的顺序排列。项目菜单过长时独立滚动，
全局入口不随其滚动。

创建项目必须先选择非空原文文件。选择语言和文件后，可勾选 **创建后执行译前准备**
（默认不勾选）。创建时直接继承总设置中的最新默认流程，创建页不再选择流程；后续
可在项目配置中调整各步骤。原文与项目信息一起提交，上传失败不会产生空项目。PDF 在提交前即可
选择解析器。服务端随后生成预览；勾选译前准备时，会接着分析全书、准备术语表。
译前准备使用已配置的默认模型并消耗模型 Token；若要先调整模型等项目设置，可保持
不勾选，再开始翻译。字幕只生成预览，不显示书籍译前准备选项。

离开页面后，解析和译前准备仍会继续。重新打开创建页 URL 可恢复文件名和进度，
出现预览不会提前结束准备状态。若文件保存后排队失败，项目会保留原文并提供
**恢复任务** 入口。开始翻译时仍会执行必要的准备步骤。

翻译总览集中提供开始、暂停、续跑和单章翻译。翻译进度、已记录的累计用时、
总 Token 用量以及匹配当前运行的最新进度始终可见。展开完整流程查看执行计划，
用量明细按“按步骤 → 按模型 → 按提供商”排列，默认显示按步骤用量条形图，
同时展示每次运行的耗时图。
项目报告默认折叠。
导出文件的生成及相关选项集中在导出页。

统计区始终显示累计 Token、请求次数、缓存命中率和已记录用时，不提供整体折叠。
状态标签使用浅色背景搭配对应颜色的文字。按模型查看时，同一提供商与模型名称的不同
推理配置合并展示，原始用量账本保持不变。用量区直接从三个分组选项开始，不再重复
展示 Token 总览图。每条用量区分缓存命中输入、未命中输入与输出，并在条形图下展示
数量及缓存命中率。命中率为命中输入除以命中与未命中输入之和；缓存信息不完整时
显示横线，缓存未知的输入单独呈现，不算作未命中。切换分组不会将不同统计维度重复
累加。运行记录按最新在前排列，显示本地化的状态、开始时间和耗时，也可展开更早记录。
计时统计整次运行，包含等待与读写，不计入两次运行之间的暂停，在运行结束或停止时
保存；不会根据 Token 用量推算模型或步骤耗时。窄屏下图表纵向排列。

暂停属于正常操作：项目和任务只显示已暂停，不展示错误提示，事件日志也不记录取消诊断。
已保存的进度可以续跑；预算限制、请求时限和模型失败仍会显示相应的诊断信息。

人工校阅以章节行展示，提供搜索、翻译状态筛选和已保存段落数。进入章节可查看原文
和已保存译文，不额外添加段落编号前缀。译文以可选中的普通文本展示，单击不会进入
编辑。右键菜单提供 **编辑译文**、**改动记录**、**复制选中文字**、**复制译文** 和
**复制原文**。触屏和键盘用户可通过小型段落操作按钮打开同一菜单；按钮上按 Shift+F10
也可打开，方向键切换操作，Escape 关闭。翻译批次保存后自动刷新，运行期间禁止编辑，
仍可复制和查看历史。审校意见保留在章节级折叠区域。

段落编辑窗口同时展示原文和自动增高的译文输入框。长文本只使用窗口的一层滚动，
保存与关闭按钮始终可见。“改动记录”页签统一展示翻译、润色、其他自动更新与人工修改。
选用历史版本只会载入草稿，点击 **保存译文** 后才会写回；关闭窗口会丢弃未保存修改。
轮询不会覆盖草稿。如果编辑期间已保存译文发生变化，需要先载入最新译文再保存；
接口也会拒绝覆盖新版本的过期请求。

新版本记录与章节更新在同一 PostgreSQL 事务内保存，独立于 Core 章节模型。
内容未变的保存不会生成重复记录。已有人工编辑事件和润色前快照仍可查看；缺少可信时间
的快照标为 **未记录时间**，不会补造丢失的中间版本。历史接口使用稳定的章节、段落 ID；
书籍段落编辑请求通过 `expected_target` 携带编辑前的译文，防止覆盖更新后的内容。

**为什么某段没有润色记录？** 改动记录保存文本变化，不逐项记录流程是否执行。
润色后文本未变，就不会新增版本。目前根据新保存的润色前快照与最终译文的差异
识别润色；其他非人工的译文替换统一显示为 **译文更新**，不能仅凭这个标签确定
来自润色还是自动修复。因此，没有润色记录不代表跳过了润色。排查是否执行时，
应结合任务保存的流程配置与已有事件；确认自动修复写回则查看全书审校的发布记录。
历史快照无法补回未记录的修改原因或中间版本。

全书审校默认打开最新运行。进行中显示实际上报的阶段、已处理／总数（总数已知时）、
本次任务用时与最近进度更新时间。用时覆盖本次任务调用，包括此前的翻译阶段，
不是审校独立用时或跨续跑的累计用时；运行中在两次进度消息之间持续计时，暂停或
结束后保留最后上报值。缺少总数时不生成百分比，未完成的结果不会显示为零问题。

问题采用可搜索、可按处理状态筛选的行列表。一条内集中显示源文位置、证据、建议译文
和写回记录。只有实际发布成功的记录才标为「已写回」，建议译文仍是建议。
原文与译文摘录取自当前章节，修改前后文本来自已保存的修订记录。同一段落经过多次
修订时，实际写回的版本取自发布索引，不会将中间草稿当成最终译文。
「前往人工校阅」使用稳定段落 ID 定位并聚焦对应段落，不自动打开编辑器。

有多次运行时，页头显示带日期与本地化状态的历史选择器，并提供返回最新结果的入口。
历史结果不显示当前任务进度；新任务准备审校时，已有旧结果会明确标注。
空的建议与发布区块不再占位，原始运行 ID、统计和检查点集中收进「技术详情」。
通过已保存的审校事件关联任务与运行，忽略其他项目或任务的缓存、Socket 进度。
自动修复只在项目设置中控制，标准流程默认开启。启动审校时使用已保存的设置，
也会保留明确关闭的选择；审校页不再提供单独开关或本次运行的临时覆盖。

导出页直接显示格式、单语／双语、生成和下载操作。排版设置折叠时仍显示当前值摘要，
折叠不会重置已填写的选项；导出请求失败时自动展开高级选项。字幕继续使用独立的
编辑与导出流程。
历史列表最多显示五条近期请求。每次成功导出后，按完成时间仅保留该项目最近五份
成功文件，失败或待完成请求不会挤掉这些文件。字幕自动生成的文件也执行同一限制，
单语与双语版分别计数；此前积累的旧文件在下一次成功导出时一并清理。过期文件及其
HTML 资源目录会被删除，上传原文、翻译状态和任务历史不受影响。已经开始的下载可继续
完成；文件系统清理失败会记录日志，并在下次成功导出时重试，不影响新文件生成。
需要长期保存的文件请在过期前下载。

总设置统一管理提供商连接、模型注册及参数、默认档位／步骤路由、创建时默认选用的模板，
以及标准流程默认值。界面语言仍是浏览器偏好，模型与默认配置持久化保存在服务端。
快速出稿关闭预理解、润色、审校与自动修复。新项目在创建时复制默认配置，已排队和
运行中的任务继续使用完整执行快照。

项目设置按档位或具体步骤选用已注册模型，并显示常用流程开关；注册新模型时可跳转
总设置。项目中不再出现连接与模型定义编辑器，高级 YAML 也不能注册模型。复杂备用
路由和预算仍通过项目 YAML 编辑；分段与性能、已保存的路由默认折叠。校验失败后保留
草稿并展开高级配置。Autofix 开关始终可见，PDF 解析器控件仅在 PDF 项目显示。
步骤下拉框直接显示实际档位；选回默认档位会清除模型覆盖，并保留备用路由。
总设置中可重命名连接和模型 ID，保存时同步更新引用。提供商与模型卡片的删除按钮统一
放在右上角，引用说明放在 ID 输入框下方；正在被引用的条目不可删除。
两处设置页都有“恢复默认配置”，先载入草稿，保存后生效。全局恢复读取服务端配置文件；
项目恢复采用当前全局默认值与本项目流程模板，并保留翻译语言。其他项目的引用会阻止
删除对应模型，保存恢复默认后的草稿时也执行这项检查。

标点规范化作为导出高级选项，只影响本次导出请求，不覆盖项目默认值；持久化的导出
默认设置仍可在项目 YAML 中修改。导出按钮会等待默认设置成功加载后启用。

创建接口使用 `multipart/form-data`：`project` 为符合 `ProjectCreate` 的 JSON
（包含可选的 `prepare` 和 `pdf_backend`），`file` 为必填原文文件。
响应包含新项目标识和当前状态；排队失败时同时返回可恢复的错误状态。
