# Web 部署与开发

[English](../web.md) · [CLI 使用指南](cli.md) · [配置](configuration.md)

Web 使用 React/Vite、FastAPI、Arq、PostgreSQL 和 Redis。普通任务与导出由两个独立 Worker 消费；领域逻辑来自 `wenyi_core`，不把 CLI 文件状态布局复制进数据库。

## 全新 Docker 部署

需要 Docker 与 Compose v2。在仓库根目录执行：

```bash
cp .env.example deploy/.env
# 编辑 deploy/.env，为 config.yaml 所选提供商填入密钥。
cd deploy
docker compose up -d --build
```

Docker 构建排除了 `.git`，安装时通过 `WENYI_VERSION` 向 `hatch-vcs` 提供版本，
使 Core、CLI 和 API 使用相同的包版本。默认 `0.0.0+docker` 表示本地开发构建。
构建发布镜像时，先在 `deploy/.env` 中将 `WENYI_VERSION` 设为对应的包版本。
普通 Git 工作区安装仍从 Git 标签生成版本。

| 服务 | 地址 / 用途 |
|---|---|
| Web | http://localhost:8080 |
| API / OpenAPI | http://localhost:8000 / http://localhost:8000/docs |
| `worker` | `wenyi:workflows`：解析、准备、翻译、Review、SRT |
| `export-worker` | `wenyi:exports`：快照导出 |
| PostgreSQL / Redis | 默认仅容器内网 |

默认启动所有服务，无需选择 profile，也无需设置构建环境变量。`up --build` 在启动前构建镜像，构建失败会报错并返回非零退出码。Dockerfile 使用普通构建指令，不依赖 BuildKit 缓存挂载或外部 Dockerfile frontend；未变化的步骤仍可复用 Docker 层缓存。后续命令在 `deploy/` 中执行：

```bash
docker compose logs -f
docker compose down
```

`down` 保留数据卷。默认使用 Debian、PyPI 和 npm 官方源；如需换源，在 `deploy/.env` 中取消对应 `DEBIAN_MIRROR`、`UV_DEFAULT_INDEX` 或 `NPM_REGISTRY` 行的注释，再运行 `docker compose up -d --build`。

Web 代理通过 Docker DNS 刷新 `api` 服务地址，HTTP 与 WebSocket 均使用该地址。API 容器重建后，代理会跟随新地址，无需重启 Web；DNS 记录缓存五秒。运行镜像须使用 Nginx 1.27.3 或更新版本，以支持[动态上游解析](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#resolve)。排查 `502` 时，对比 `http://localhost:8000/health` 和 `http://localhost:8080/api/health`，并检查 `docker compose logs web api`。旧部署若仍保留过期的 API 地址，可执行 `docker compose exec web nginx -s reload` 临时刷新；重新构建 Web 才会安装永久修复。

本次数据库结构面向全新部署，不执行旧项目/策略/数据库迁移。保留旧部署时，新版使用独立 Compose project、数据库和卷，例如运行 `COMPOSE_PROJECT_NAME=wenyi-new docker compose up -d --build`。不要对需要保留的数据卷执行删除操作。

### 可选的 Buildx 开发构建

已安装 Docker Buildx 插件（可用 `docker buildx version` 检查）时，在 `deploy/` 下启用带下载缓存的 Dockerfile：

```bash
DOCKER_BUILDKIT=1 COMPOSE_BAKE=true docker compose \
  -f docker-compose.yml -f docker-compose.buildx.yml build &&
  docker compose -f docker-compose.yml -f docker-compose.buildx.yml up -d --no-build
```

上述命令启用 BuildKit/Bake，构建和启动均使用 Buildx 覆盖文件，并用 `&&` 保证构建成功后才启动。覆盖文件仅切换 Dockerfile，沿用相同的服务、镜像名称、凭证、换源配置和数据卷。apt、uv 和 pnpm 下载缓存可在多次构建之间复用，缓存属于所选 builder。默认 Dockerfile 仍不要求 BuildKit；修改安装步骤时需同步两个版本。运行 `docker compose up -d --build` 即可恢复普通构建。

若配置的 PyPI 镜像在解析 `hatchling`、`hatch-vcs` 等构建依赖时返回 `403 Forbidden`，将 `deploy/.env` 中的 `UV_DEFAULT_INDEX` 改为 `https://pypi.org/simple` 后重新构建。镜像拒绝访问可能被报告为“找不到包”，清理 BuildKit 缓存不能解决镜像访问问题。拆分构建和启动时，用 `&&` 连接；构建失败后单独执行 `up --no-build` 会继续使用已有镜像。

Compose 可将构建委托给 [Buildx Bake](https://docs.docker.com/guides/compose-bake/)。此可选路径需要可用的 Buildx/BuildKit 环境，普通部署不需要安装。

## 共享配置与凭证

API、普通 Worker、导出 Worker 都加载 `deploy/.env`，只读挂载同一 `config.yaml`，并共享 `/data`。更改提供商环境变量后重建相关容器；修改配置后新任务读取新默认值，项目显式设置仍优先。

| 环境变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` 等 | 只需设置实际路由涉及的提供商凭证；自定义提供商在 `.env` 增加 `api_key_env` 指定的名称。 |
| `MINERU_API_KEY` | 仅使用 MinerU PDF 解析时需要。 |
| `WENYI_CONFIG` | 应用读取的核心配置路径；容器固定 `/app/config.yaml`，本地默认 `config.yaml`。 |
| `WENYI_CONFIG_FILE` | Compose 宿主配置文件，默认 `../config.yaml`，相对 `deploy/`。 |
| `DATA_DIR` | 上传原件、解析资源与导出成品目录；容器固定 `/data`。 |
| `DATABASE_URL` / `REDIS_URL` | 本地开发连接地址；Compose 覆盖为内部服务地址。 |
| `WENYI_VERSION` | Docker 构建时传入的包版本，默认 `0.0.0+docker`；发布镜像须显式设置发布版本。 |
| `DEBIAN_MIRROR` / `UV_DEFAULT_INDEX` / `UV_IMAGE` / `NPM_REGISTRY` | 可选构建镜像源与官方 `uv` 镜像标签；默认使用官方源；需要换源时取消 `deploy/.env` 中对应行的注释。 |
| `WENYI_API_TOKEN` | 可选静态 token；HTTP 使用 Bearer 鉴权，WebSocket 使用连接后的首个 `{"token":"…"}` 消息鉴权，前端自动发送。 |
| `WENYI_CORS_ORIGINS` | 允许的源，逗号分隔；默认 `*`。启用 token 时允许已配置来源的预检请求，鉴权错误响应也保留 CORS 响应头。 |

自建 WebSocket 客户端须在连接后 10 秒内发送 JSON 首包 `{"token":"…"}`；未配置服务端 token 时也发送首包（token 可为空）。通过鉴权后才接收项目快照和实时事件。

数据库存储项目、章节、段落、术语、Review 证据/检查点、Autofix 发布索引、字幕缓存、用量和计时。`DATA_DIR` 不存这些可变状态的 JSON/SQLite 副本。

**Web 和 Desktop 删除项目均为永久操作。** 确认提示覆盖上传原文、译文、
历史记录、缓存和项目导出文件。Web 会清理 `DATA_DIR` 下该项目的目录，并
级联删除 PostgreSQL 中的项目数据；不影响另存的下载文件或其他项目。
任务仍在进行时不能删除。清理失败会报错并保留数据库记录以供重试，
部分文件可能已经被清理。在支持读取已取消目录链接文件的系统上，已打开的
下载可以继续完成。不会批量清理历史残留目录。

### PDF

后端镜像从 Astral 官方镜像复制 `uv`/`uvx`，通过 frozen `uv sync` 仅安装 Web 依赖闭包，并将虚拟环境加入 `PATH`，启动时不再安装额外 Python 依赖。镜像不包含本地 PDF 渲染库及字体。MinerU 为默认解析后端，解析缓存与上传预览共用。

BabelDOC 作为独立 HTTP bridge 部署。将 `pipeline.pdf_backend` 设为 `babeldoc`，把 `pipeline.babeldoc_bridge_url` 设为 API 与两个 Worker 都能访问的地址。bridge 的 `127.0.0.1` 指当前容器，不是宿主机。此 Compose 不自动下载或启动 BabelDOC 服务。PDF 导出仅对已保存的 BabelDOC 项目开放，通过 bridge 回填保留排版，不再提供本地 PDF 引擎选择。导出格式依据各项目已保存的状态，而非当前解析器设置。MinerU 及其他书籍项目可导出 EPUB、DOCX、HTML、TXT 或 Markdown；不支持的 PDF 请求在创建导出任务前返回 HTTP 422。

## 本地开发

需要 Python 3.10+、`uv`、Node 22、pnpm 9，以及 PostgreSQL 16 / Redis 7。先启动数据库，开发覆盖文件显式绑定宿主机回环端口：

```bash
cp .env.example deploy/.env
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.dev.yml \
  up -d postgres redis
uv sync --all-packages --group dev
pnpm install --frozen-lockfile
export DATABASE_URL=postgresql://wenyi:wenyi@localhost:5432/wenyi
export REDIS_URL=redis://localhost:6379/0
export DATA_DIR=./data
export WENYI_CONFIG=config.yaml
export DEEPSEEK_API_KEY=your-key
```

在四个终端中使用相同应用环境变量：

```bash
uv run uvicorn wenyi_api.main:app --reload --port 8000
uv run arq wenyi_api.workers.WorkerSettings
uv run arq wenyi_api.workers.ExportWorkerSettings
pnpm -C apps/web dev
```

Web 开发地址为 http://localhost:5173，Vite 代理 `/api` 与 `/ws` 至 API。API 初始化全新数据库结构。仅起普通 Worker 不会消费导出队列。

若不想启动任何后端、只想在浏览器里点着看界面，运行 `MOCK_API=1 pnpm -C apps/web dev`。Vite 会用 Playwright 测试同一套 fixture 数据（`packages/ui/tests/e2e/fixtures.ts`）应答 `/api`：所有页面都带示例数据打开，按钮操作直接在 mock 上完成，不接触真实服务。进度 WebSocket 不可用时界面自动退回轮询 mock API。不设 `MOCK_API` 时行为与平常一致，代理到真实 API。

## 设备支持

前端面向电脑使用。UA（User-Agent）识别为手机或平板时，仅显示 **请使用电脑打开**，不挂载工作台、不读取项目数据，也不连接项目进度。检测只依据 UA，不按窗口宽度、触摸能力或平台提示阻止访问；使用桌面 UA 的设备按电脑处理。

电脑窄窗口仍使用同一套桌面侧栏和多栏布局，空间不足时可在内容区横向滚动。调整窗口大小不会卸载页面或丢失未保存草稿，不再提供独立的手机导航或上下堆叠的移动端工作台。

## 界面语言

界面默认使用英语，不自动跟随浏览器语言。打开全局 **设置 → 通用 → 界面语言**，可选择
**English** 或 **简体中文**。尚未创建项目或任务正在运行时也可切换，此偏好不属于项目设置。

通过共享侧栏底部的**设置**进入，空列表也可使用。设置使用独立页面，侧栏改为设置分类，
不显示项目导航。`/settings` 默认打开通用；固定在侧栏左下角的**返回**回到进入设置前的页面，
直接访问设置地址时则回到项目列表。

选择立即生效，刷新后保留，并在同一站点的多个标签页之间同步。偏好保存在浏览器的
`wenyi.locale` 中，不写入项目配置；没有已保存语言或保存值不受支持时，回退到英语。

界面语言只改变标签及数字／日期格式，不修改源语言、目标语言、模型配置、书籍内容、
术语或模型生成的分析。服务端错误和实时日志按收到的内容展示。
开发说明见共享的[前端国际化指南](../../packages/ui/src/i18n/README.md)。

## 使用流程

Desktop 与 Web 共用这些工作台页面，截图见[界面预览](README.md#界面预览)。

翻译总览自动更新状态、已保存段落数、用量和运行用时。当前运行的计时每秒递增，包含等待模型响应的时间；Token 用量在提供商返回实际统计后更新。WebSocket 事件触发刷新，轮询作为后备，重连后自动同步。暂停或完成时自动读取最终累计统计，无需刷新页面；恢复运行保留之前的累计值，不计入暂停期间的时间。实时统计使用临时 Redis 快照，与持久用量账本分开；心跳过期后本地计时停止递增，直到收到新的统计。

项目页面仅在任务活动期间轮询，包括排队和正在暂停；已完成、已暂停及其他空闲项目在同步最终落盘数据后停止周期请求。项目列表中没有活动项目时也停止轮询。打开页面、保存编辑、开始／恢复任务及已连接的进度事件仍可触发读取；导出任务独立刷新至结束。没有订阅进度事件的空闲页面，如需查看其他客户端启动的任务，请重新进入或刷新页面。并发编辑仍由服务端校验，冲突时读取最新值并保留当前草稿。

**缓存读取 / 全部输入**使用已报告读取除以全部输入 Token，分母包含未知输入。图表分别展示读取、
写入、普通输入和分类未知，仅在有数据时显示 5m/1h 写入小计。缺失计数显示 `—` 而非零；
「输入 Token（缓存写入）」为零时隐藏，非零值和未知状态 `—` 仍显示。
已知小计可能只覆盖部分调用。没有可用读取计数或输入总量时，
比例为未知；不可能成立的缓存分类也按未知处理。历史未命中可能包含缓存写入，不能视为普通输入。
支持的用量协议与账本兼容规则见[用量统计](cli.md#用量与事件日志)。这些计数不能直接确定费用。

1. 点击共享侧栏的**创建项目**，在项目列表上打开居中的对话框。项目列表仍在背后显示，但不能操作；直接访问 `/projects/new` 也打开同一对话框，不是独立页面。焦点首先进入「项目名称」，Tab 不会离开对话框；下拉框打开时，Escape 先关闭下拉框。点击「取消」、关闭按钮、遮罩或按 Escape，返回之前的页面（直接访问时返回项目列表），不创建项目；焦点回到侧栏入口，再次打开是全新表单。浏览器后退也可离开对话框。窗口高度不足时表单可滚动，顶部关闭按钮始终可见。
   选择源／目标语言及非空 EPUB、DOCX、FB2、TXT、Markdown、HTML、PDF 或 SRT 文件。可将单个文件拖入原文区域，或点击「浏览文件」，再点击「创建项目」上传。两种方式使用相同的格式和空文件校验；一次拖入多个文件会被拒绝。上传中不能更换原文或关闭对话框，关闭不是取消任务的入口。上传失败保留表单和原文，可直接重试。旧链接 `/projects/new?project=<id>` 保留只读原文和已有预览／恢复操作。书籍可选勾选「译前准备」；PDF 解析器在上传前选择。
   上传中仍可通过浏览器后退离开，但这不会取消请求。项目可能在后台创建，完成后不会强制跳离当前页面。
2. 创建成功后立即进入项目总览，解析或可选的译前准备继续在后台执行。解析完成即可通过「查看目录与原文」打开章节列表和只读原文，不必等待模型预处理。勾选译前准备时，也会先解析，再构造和校验模型客户端，因此缺少凭据或后续 AI 失败不会隐藏已成功解析的原文。初始化完成前，标题和译文保持只读。总览自动更新任务状态，排队失败时也在项目内显示错误与恢复入口；匹配的解析结果在准备时复用。
3. 创建对话框使用平铺表单填写项目名称、语言方向、原文文件和翻译方式，操作按钮固定在可滚动表单下方。书籍只在这里通过两段切换按钮选择「标准翻译」或「三译合润」。默认标准，不继承全局模式；精翻开启本项目润色并内置三分支并发，不提供并发选项。总设置和项目配置都没有模式或模板选择器，新请求不再支持快速出稿。需要微调时进入「项目配置」调整其他步骤及注册模型选择，启动翻译前可校验实际路由；更换翻译方式需创建新项目。
4. 开始执行，在进度页查看状态；安全边界暂停后用恢复继续实际任务类型。如果暂停请求到达时任务已完成，或活动运行已经改变，接口返回 HTTP 409，不会把已完成项目留在“正在暂停”；刷新可查看最新状态。
5. 书籍可编辑术语、风格、段落并查看全书审校历史、建议和实际修复记录；SRT 显示字幕条目及时间戳编辑入口。
6. 导出选择格式和单语/双语，独立 Worker 读取已保存快照。每次导出有独立文件位置，完成后下载。

API 仅允许未初始化项目替换原文。预览缓存失效失败时，原引用和缓存保持完整。
如果原文发布结果不确定，即使请求报错也会保留完整的新文件；重试前先重新读取项目。
这里优先保护可能已经发布的原文，不会为了自动清理未引用上传而冒误删风险。

**人工校阅**有独立导航入口，与全书审校分开。解析完成、AI 预处理之前即可显示章节列表；未初始化的书籍只显示原文，不提供编辑、历史或初稿操作，完成准备后才显示包含未完成译文的工作台。任务活动期间，详情页每 3 秒读取已落盘的段落，每批译文保存后即可查看，无需等整章完成；暂停和完成后不再轮询章节及改动记录。待翻译段落显示“等待译文落盘”，有意保存的空译文仍计为完成。任务运行时可查看，暂停后可编辑已保存段落。自动刷新保留正在编辑的草稿。

大章节保留完整文本，支持原生查找、跨段选择和段落深链接。所有段落共用一个按需打开的操作菜单；章节审校记录首次展开时才挂载。离开章节会取消不再使用的进行中正文请求。

在段落菜单或编辑器中打开「精翻初稿」，按需查看归档的 T1／T2／T3。
T1 是润色前对照稿，不是选出的赢家；最终译文来自三稿的一次综合润色。
归档综合润色结果与当前正式译文分开展示，后者可能已由人工或 Review 修改。
该视图仅供查看，翻译运行时也可使用，切换页签不会丢失未保存的编辑。
标准项目或缺失、冲突、不匹配、损坏的归档会显示明确的不可用状态，
不会为查看初稿重新请求模型或补造译文。
任务运行时，尚未完成发布的归档会自动刷新；不可用状态也可手动重新加载。
有意保存的空译文会明确标注，不显示成无说明的空白。

从段落操作菜单打开**改动记录**即可对比版本。润色及人工修改默认按词高亮段内差异：删除内容为红色并带删除线，新增内容为绿色并带下划线；**前后全文**可切换到原始版本。分词使用项目目标语言，旧浏览器回退为字符级比较；空格、标点和换行也参与对比。文本过长或改动过多时回退到前后全文，仅展开的记录计算差异。未记录独立润色版本的旧项目可查看**初译 → 当前版本**，并明确提示当前版本可能包含后续人工修改或自动修复。对比是只读操作；载入历史版本仅更新草稿，保存后才生效。

项目列表和项目页面共用一个常驻侧栏，包含**创建项目**、**项目列表**、当前或上次打开项目的功能导航，以及底部的**设置**，不再使用首页悬浮入口。进入设置后，侧栏替换为设置分类和**返回**按钮。点击“收起侧边栏”扩大内容区：导航收成图标栏，悬停显示名称，电脑窄窗口也保留这一行为。宽度和文字在 280 毫秒内平滑过渡。浏览器记住展开状态和上次打开的项目，切换页面或刷新后保留；导航和页面延迟加载不会卸载整个外壳。

全局**设置**每次显示一个分类：**通用**、**模型与接口**、**默认模型**、**翻译流程**、**PDF 解析**或**高级**，对应可直接访问和刷新的 `/settings`、`/settings/providers`、`/settings/defaults`、`/settings/workflow`、`/settings/mineru` 和 `/settings/advanced`；未知分类回到通用。切换分类或浏览器前进／后退会保留配置、ID 和 YAML 草稿；离开设置或刷新页面会丢弃未保存的草稿。保存、校验与恢复默认作用于整份配置草稿，操作栏固定在底部。提示链接会打开未完成 ID 修改或未校验 YAML 所属的分类。模型与接口下的**测试连接**会向每个已保存的模型配置发送一次简短的真实请求（`POST /settings/models/ping`），报告是否连通、延迟和失败类别；每次点击会消耗少量 token。

设置分类使用完整内容区宽度，分类名称放在页顶，不再另占一列重复显示。**分段与性能**、**按步骤选择模型**和**高级 YAML 配置**直接显示，不再使用折叠分组。项目配置页保留原有的标题列和紧凑折叠布局。

**返回**上方不显示分隔线。全局设置操作栏始终贴合内容区底边，滚动到底时也不会上移。

Web 与 Desktop 的项目列表、术语表、全书审校、事件日志及全局／项目设置不再显示介绍性副标题，创建项目和段落编辑弹窗也移除重复说明。项目配置保留前往总设置管理模型的链接。高级 YAML 仅在编辑后显示未保存状态摘要；成本、只读、安全与错误提示仍保留。

两端仍明确显示操作约束：导出历史提示仅保留最近五份文件，需另行保存；审校空状态提示完成全部章节翻译后才能启动审校；术语导入提示支持 CSV/JSON，以及 CSV 必须包含的 `source`、`target` 列头。

同页历史导航会关闭已展开的下拉菜单，但不重置配置草稿。通知固定在视口内，不跟随最后点击的按钮：成功提示停留一秒，错误和警告停留十秒，其他消息停留五秒。错误可手动关闭；术语新增／编辑失败也会在弹窗内持续展示，直到重试或关闭弹窗。

长章节标题自动换行，不挤压状态标签和操作。没有标题的章节在总览与人工校阅中显示为“未命名章节”。原文与译文始终直接并排显示，不另设表头行。阅读和编辑时，长文本及引用链接在内容区内换行；电脑窄窗口可横向滚动内容区，不切换为手机布局。

术语表在切换类型筛选时保持一致的紧凑行高与列宽。过长的源词和译词以单行省略显示，悬停文本或打开编辑窗口可查看完整内容；表格在需要时保留横向滚动。

Web 和 Desktop 在任务排队或运行时，仍可通过眼睛按钮打开**术语详情**，查看并复制完整源词、译词、别名、备注及日语原文的读音；类型和性别仍显示，但不可修改。新增、导入、编辑、删除和冲突处理继续禁用。已打开的词条弹窗会跟随任务状态：任务开始后转为只读，停止后恢复编辑。

Web 和 Desktop 的读音不再单独占用表格一列。日语原文项目在新增／编辑词条详情中显示读音字段，搜索提示也包含读音。其他原文语言隐藏该字段和提示，即使目标语言是日语；尚未检测的 `auto` 原文也先隐藏，检测为日语后再显示。隐藏字段不会删除已有读音，编辑其它词条字段时也不会清空它。

**目录与标题**按已有章节对照显示原标题与译名，支持搜索、跳转人工校阅，以及通过铅笔按钮编辑译名。保存后写入服务端，各浏览器均可读取，并同步关联的 EPUB 目录节点，包括原标题和目标位置一致的 NAV/NCX 条目。后续导出使用已保存标题，已有导出文件不变；正文标题需在人工校阅中单独修改。任务运行时须先暂停再编辑。同一标题被其他页面修改时，会保留当前输入，要求载入最新标题后再保存。当前页面按章节展示，尚不包含完整 EPUB 层级编辑或自动标题对齐。

Web 和 Desktop 的**风格 & 概要**支持编辑全部风格维度：体裁、语调、叙事、节奏、
语域、对话风格和修辞。**风格概览**中的**保存**会一并保存这些字段和**风格指南**；
全书概要单独保存。保存某一部分或章节摘要时，不会丢弃其它部分尚未保存的草稿。
任务运行期间仍禁止编辑。
风格和全书概要草稿按项目隔离，在同一次应用会话内跳转其它页面后仍会保留；
草稿仅存于内存，刷新或关闭应用会丢弃未保存的修改。
分析保存请求尚未完成时，即使跳转其它页面再返回，相关编辑器仍保持只读，
避免在同一次应用会话中对同一项目重叠提交。

**风格 & 概要**不再展示独立角色列表，也不提供人物管理入口。
从侧边栏打开**术语表**，选择**人物**筛选，统一维护原名、译名、性别、备注和别名，日语原文项目还可维护读音。搜索支持源词、
译词、别名、读音和备注，不区分大小写，并忽略查询首尾空白；类型筛选也作用于搜索结果。

Web 和 Desktop 的术语表、类型筛选和添加／编辑弹窗统一按界面语言显示全部 11 种内置类型：
人物、地点、组织、术语、技法、物品、设定、称谓、敬称、口癖和固定表达。
存储和导出的类型 ID 仍使用英文；自定义类型在表格中保留原始标签。

在**术语表 → 导出 → Anki 牌组（.apkg）**中导出完整术语库，不受搜索、类型筛选、分页或勾选影响。
将文件导入 Anki 后，会在 `Wenyi` 父牌组下创建项目专属的书籍牌组，再按术语类型建立子牌组。
全部类型（包括自定义类型）均会导出；请在 Anki 中筛选或暂停不想学习的卡片，而不是在导出时排除。

避免不同类别混淆或意外创建额外的层级。

每个词条生成一张识别卡：正面为原文，背面展示已有读音、本书译法、备注、别名，以及书籍、类型和语言信息。
标签包含 `wenyi::type::person`、`wenyi::project::<项目 ID>` 和源／目标语言标签。
译文是本书采用的表达，不是词典释义。导出不会生成读音、例句、反向卡或音频，不调用模型，
不修改术语库，也不包含尚未解决的候选译法。

同一项目中原文不变的词条重复导出时保持笔记身份稳定，Anki 可以更新内容而不重复建卡或重置复习进度。
内容更新取决于 Anki 的导入选项与修改时间检查；修改原文词条或改用另一项目会创建新笔记。

### Worker 异常退出后的恢复

Worker 启动独立的异步恢复循环，每 30 秒检查一次数据库中超过 2 分钟未更新的排队/运行任务。检查先尝试获取对应会话锁，确认没有仍在执行的 Worker；正常持锁的长任务不会仅因运行时间长而被判为失联。排队任务还会核对 Redis 队列状态。

确认失联后，普通工作流记录为中断，所属最新工作流项目置为 `paused`，可通过“恢复”继续原任务类型和保存进度。导出任务和导出记录置为 `error`，重新创建导出即可重试。导出拥有持久化任务身份及独立执行锁，防止重复投递重复生成文件，并支持异常退出后的状态恢复。

## 接口、检查与排错

共享 app 的路由/schema 定义是接口类型源。运行中的 `/openapi.json` 仍可用于检查，
但类型生成不需要启动 API、PostgreSQL、Redis 或提供凭据。安装工作区 Python 依赖及
前端依赖后，离线生成或检查契约：

```bash
pnpm gen:schema  # Update shared types from the shared app factory, offline
pnpm check:schema  # Compare temporary generated types; does not change tracked files
uv run --no-sync ruff check packages/core packages/cli apps/api
uv run --no-sync pytest -q -n auto
pnpm -C apps/web typecheck
pnpm -C apps/web build
pnpm -C apps/web exec playwright install chromium
pnpm -C apps/web test:e2e
```

CI 在前端类型检查前执行 `check:schema`。生成过程使用不可调用的运行端口，不启动生产
lifespan；仅将 schema 产物中依赖安装版本的信息标准化。`GET /capabilities` 继续提供
运行时语言、格式、提供商和操作注册信息。

Web 和 Desktop 共用 `packages/ui/vite.shared.ts` 中的分包规则：React、React DOM
和 Scheduler 独立为 `react-runtime` chunk，页面继续保留现有懒加载分包。构建两端后，
运行 `pnpm test:frontend-boundaries` 检查平台隔离，并验证每个压缩后的 JavaScript
chunk 不超过 Vite 默认的 500 kB 限制。体积增长时应继续拆包，而不是调高
`chunkSizeWarningLimit`；该检查不限制总下载量。

设置 `WENYI_TEST_DATABASE_URL` 运行真实 PostgreSQL 集成测试，测试会创建独立 schema 并在结束时删除它；使用测试数据库。CI 同时提供 Redis 服务。

- 任务一直排队：确认普通/导出 Worker 与 API 使用同一 Redis，并监听对应队列。
- PDF 解析失败：检查所选解析后端的凭证、bridge 地址及服务可用性。
- 缺少模型凭证：校验实际操作路由涉及的提供商环境变量，不必填写未使用提供商。
- 本地连不上数据库：使用 `docker-compose.dev.yml` 开放回环端口，或连接独立安装的数据库。
- 旧配置字段错误：按配置页校验结果移除旧 QA、回译、字符预算等字段；当前 Web 不提供旧项目自动迁移。

在 `deploy/` 下可用 `docker compose logs -f api worker export-worker` 查看任务失败原因。离线/浏览器验证结果与真实模型的翻译质量评估应分别记录。

### 关联编号与指标

响应包含 `X-Request-ID`，服务端失败还包含 `X-Error-ID`，可据此关联 HTTP 失败和
服务端日志。Docker 日志配置对每条日志只输出一条 JSON 记录，并带上已绑定的请求编号；
其他入口可用 `WENYI_LOG_FORMAT=json` 选择 JSON。内部 traceback 只保留在服务端日志中，
不通过项目事件 API 返回；读取历史事件时也会过滤该字段。

`GET /metrics` 输出 Prometheus 文本，使用与其他 API 路由一致的 `API_TOKEN` 鉴权。
开启鉴权时须给采集器配置 bearer token。API 和 worker 必须连接同一个 Redis 数据库：

- `wenyi_tasks_total{status,code}` 统计结束的**流程**任务（`done`、`paused`、`error`），
  不统计导出任务。
- `wenyi_llm_retries_total{provider,reason}` 统计实际重试等待，按 call ID 和 attempt 去重；
  重试耗尽通知不额外计为一次重试。
- `wenyi_queue_depth` 从项目目录库读取已接纳、仍在排队的流程和导出任务数，不含运行中任务。

Web 计数通过 Redis 跨进程共享，保留时间与对应 Redis key 一致；最近的任务/重试身份在
20,000 条有界窗口内去重。Desktop 则使用应用实例独立的内存计数，重启后归零，
队列深度仍读取自身 SQLite 目录库。计数写入尽力完成，不使流程失败；指标存储或目录库
不可用时返回 HTTP 503，而不是误导性的零值。指标不是用量/计费账本，Wenyi 不自动安装采集器。

### 提供商设置与流程视图

全局 **设置** 统一管理提供商连接、模型注册、默认档位与步骤路由，以及通用流程默认值，不提供翻译模式或流程模板。连接和模型 ID 可以重命名，存在引用的条目不能删除；恢复默认配置先载入草稿，保存后生效。**项目配置** 只选用已注册模型并调整其他流程设置，不注册提供商或模型，也不切换创建时选定的翻译方式。高级 YAML 支持按操作路由与回退。

凭证仍保存在服务端环境变量中；表单只填写变量名，不填写原始 API Key。**模型名称**旁的刷新按钮会获取该连接的模型列表（`POST /settings/models/list`）供下拉选择；请求使用编辑中、未保存的连接，并从服务端环境变量读取密钥。为防止草稿读取任意服务端变量，只接受提供商默认变量或已保存配置中用过的变量名；使用新变量名需先保存。请求只发送一次、不重试，不消耗 token。配置检查会校验路由与凭证是否可用，但不会真正发送模型请求。检查已保存配置前请先保存。运行中的项目须先暂停再编辑；新建或恢复的任务会捕获已保存设置。

修改连接会清空已获取的模型列表。修改前发出的请求，即使稍后返回列表或错误，也会被忽略；再次获取即可查询修改后的连接。

Web 与 Desktop 在释放项目运行锁后才发布流程任务的终态。成功完成还会等待完成事件写入和实时统计收尾，因此在观察到任务完成后立即保存配置，不会再与该任务的收尾争抢运行锁。排队中或执行中的任务仍会使项目修改保持只读。

**PDF 解析**分类仅提供 MinerU 部署说明。使用 MinerU 时，在 API 与 worker 环境中设置
`MINERU_API_KEY`，它独立于模型 API Key。Web 不提供 Desktop 的手动 MinerU 密钥输入
或安全存储接口。

在 **翻译总览** 中，**当前翻译流程** 以扁平分区直接展示最近一次非导出任务的类型、状态和当前进度，不再使用嵌套卡片或折叠步骤清单。阶段文字和计数来自真实进度回调，不根据配置中启用的步骤推测完成情况；润色仍在翻译批次内执行。任务完成后仅保留完成状态，不重复展示最终回调或等待提示；暂停和失败时，如有记录则保留最后上报的阶段。首次运行前显示 **尚未开始**。总览不再展示或请求项目报告，仍保留用量、运行耗时、章节状态和 **查看目录与原文**。启用哪些步骤可在 **项目配置** 中调整。
